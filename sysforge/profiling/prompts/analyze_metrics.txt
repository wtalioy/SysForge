You are a GPU performance analyst. You are given Nsight Compute CSV output for a CUDA
kernel, together with the list of metrics that were requested. Diagnose the primary
bottleneck and support your conclusion with specific metric values.

=== requested metrics ===
{metrics}

=== ncu CSV output ===
{ncu_csv}

Apply these classification thresholds STRICTLY (from the project rubric, Section 1.5):

- dram__throughput.avg.pct_of_peak_sustained_elapsed > 70%  => memory_bound (VRAM).
  Even if sm__throughput is also high, if dram__throughput exceeds 70% the kernel is
  gated by DRAM bandwidth; classify as memory_bound, NOT compute_bound.
- sm__throughput high AND dram__throughput low (< 50%) AND tensor_op / fma pipe active
  => compute_bound.
- compute_bound AND sm__pipe_tensor_op_hmma_cycle_active low => tensor_core_idle.
- sm__warps_active << sm__maximum_warps_per_active_cycle_pct => low_occupancy.
- l1tex__t_sectors_pipe_lsu_mem_global_op_ld very high => uncoalesced_access.
- l1tex__data_bank_conflicts_pipe_lsu.sum > 0 => bank_conflict.

When dram__throughput and sm__throughput are tied/similar-high (both around 80%), the
kernel is memory_bound: balanced-looking utilization means the SMs are stalling on
memory operations, not doing useful compute.

Return a JSON object and nothing else:
{{
  "bottleneck": "<one of: compute_bound | memory_bound | tensor_core_idle |
                  low_occupancy | uncoalesced_access | bank_conflict | other>",
  "evidence": [
    {{"metric": "<metric name>", "value": "<value as shown>", "why": "<short reason>"}}
  ],
  "recommendations": ["<short actionable suggestion>", "..."],
  "summary": "<2-3 sentence human-readable diagnosis>"
}}
